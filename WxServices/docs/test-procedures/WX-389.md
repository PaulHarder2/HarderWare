## Steps 1–2 — executable immediately (repo half)

### 1. Every LOCAL link in every `landscape-scans/*.md` resolves — file AND anchor

Save the checker once; the control and the mutants both use it.

**Two things it does that an obvious version would not.** It **strips fenced blocks and
backtick spans before harvesting anchors**, because this file and `_evaluated.md` both
*document* the `<a id="…">` convention in prose — without stripping, a documented id
counts as a real target and can mask a deleted one. And it **resolves the `#fragment` of
a cross-file link against that file's own targets**, not merely the file's existence,
since step 5 exists precisely because a link to a missing anchor lands silently at the
top of a file.

```bash
cat > $WX389_TMP/wx389-linkcheck.py <<'PY'
import re, os, glob
D='landscape-scans'
def slug(s): return re.sub(r'\s','-',re.sub(r'[^\w\s-]','',s.strip().lower()))
def strip_code(x):
    x=re.sub(r'```.*?```','',x,flags=re.S)      # fenced blocks
    return re.sub(r'`[^`\n]*`','',x)            # inline code spans
def targets(text):
    # BOTH harvests run on stripped text: an EXAMPLE heading or an EXAMPLE <a id>
    # inside a fence or backticks is documentation, not a real target.
    s=strip_code(text)
    a={slug(m.group(2)) for m in re.finditer(r'^(#{1,6})\s+(.*)$',s,re.M)}
    a|=set(re.findall(r'<a\s+id="([^"]+)"',s))
    return a
def check(overrides=None):
    ov=overrides or {}
    def read(p): return ov[p] if p in ov else open(p,encoding='utf-8').read()
    cache={}
    def tgt_of(p):
        if p not in cache:
            cache[p]=targets(read(p)) if (p in ov or os.path.exists(p)) else None
        return cache[p]
    srcs=sorted(set(glob.glob(os.path.join(D,'*.md')))|set(ov))
    # FAIL LOUD ON WRONG CWD. Without this the glob returns [], the loop never runs,
    # check() returns [] and step 1 prints a confident CLEAN having checked nothing.
    assert srcs, "no landscape-scans/*.md found - wrong working directory?"
    bad=[]
    for p in srcs:
        for m in re.finditer(r'\]\(([^)]+)\)', strip_code(read(p))):
            raw=m.group(1).strip()
            if raw.startswith(('http://','https://','mailto:')): continue
            f,_,frag=raw.partition('#')
            # normpath so a link OUT of landscape-scans/ resolves to its real location
            dest=p if f=='' else os.path.normpath(os.path.join(D,f))
            t=tgt_of(dest)
            if t is None:
                bad.append((os.path.basename(p),'missing file',f)); continue
            if frag and frag not in t:
                bad.append((os.path.basename(p),'missing anchor',raw))
    return bad
PY
python3 -c "exec(open('$WX389_TMP/wx389-linkcheck.py').read()); print('control ->', check() or 'CLEAN')"
```

**Expect:** `CLEAN`.

⚠️ **LOCAL links only — this step says nothing about external URLs.** `check()` skips
`http://`, `https://` and `mailto:` targets, so a dead vendor citation reports `CLEAN`.
That is deliberate: the scan reports are almost entirely vendor links, and
`docs.coderabbit.ai` returned **403 to one client and 200 to another within hours** on
2026-08-01 — a gate that fails on somebody else's transient rate limit teaches its reader
to wave it through. **Link rot in the citations is a real decay problem and it is not
covered here**; if we ever want it, it belongs in a periodic sweep that reports for
triage without blocking a landing.

> ⚠️ **ONE EXPECTED FAILURE THAT IS THE MECHANISM WORKING, NOT A BUG TO FIX.** In the
> window between a new report merging and its decisions being recorded, the report's
> `**Decisions.**` footer points at a `## YYYY-MM` section that does not exist yet —
> writing it is the *last* step of reacting to the scan (step 5). The checker will
> report `missing anchor  _evaluated.md#YYYY-MM`, and that is **exactly the completeness
> check this register was built to provide**: a scan that has not been dispositioned
> says so. **Do not "fix" the footer.** Record the decisions, then re-run.

**Negative controls — run these too, or step 1 proves nothing.** Each mutant must be
**assigned to a variable**; `t.replace(...)` returns a new string and discarding it is
itself the failure this control exists to catch.

```bash
python3 - <<'PY'
exec(open('$WX389_TMP/wx389-linkcheck.py').read())
p='landscape-scans/_evaluated.md'
t=open(p,encoding='utf-8').read()
m1 = t.replace('](#sonnet-5-runtime)','](#zzz-no-such-anchor)',1)
m2 = t.replace('<a id="opus-5-claude-code"></a>','',1)
m3 = t.replace('](2026-07.md)','](2026-99.md)',1)
m4 = t.replace('](2026-07.md)','](2026-07.md#no-such-heading)',1)
# m5 is the ONLY mutant that exercises strip_code: delete the real anchor AND leave a
# BACKTICKED mention of the same id behind, as documentation would. Without the
# stripping, that mention is harvested as a real target and the deletion is masked.
m5 = t.replace('<a id="opus-5-claude-code"></a>','',1) \
      .replace('(`<a id="…">`)','(`<a id="opus-5-claude-code">`)',1)
for n,mut in (('1 broken in-file anchor',m1),
              ('2 stable anchor deleted',m2),
              ('3 missing report file',m3),
              ('4 bad cross-file fragment',m4),
              ('5 anchor deleted, BACKTICKED mention left',m5)):
    print(f"mutant {n:44} ->", check({p:mut}) or "CLEAN  <-- CHECKER IS DEAD")
PY
```

**Expect:** every mutant reports at least one problem.

**Mutant 5 is the one that matters, and it is the only one that tests `strip_code`.**
It deletes the real anchor *and* leaves a backticked mention of that same id in the prose
— which is what a future editor documenting the convention would do. If `strip_code` is
removed or broken, the mention is harvested as a real target, the deletion is masked, and
m5 reports `CLEAN`.

⚠️ **Mutants 1–4 pass with `strip_code` replaced by the identity function** — verified.
They are worth keeping, but **none of them covers the stripping**, and an earlier version
of this procedure wrongly claimed mutant 2 did.

**If ANY mutant reports `CLEAN`, the checker is dead and step 1's pass is meaningless.**

### 2. The scope note is present, and the file honours it

```bash
grep -n "Scope — this file is PUBLIC" landscape-scans/_evaluated.md
grep -nEi "(trig|env|wf|conn)_[A-Za-z0-9]{20,}|connector_uuid|[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}|sk-ant-|gh[pous]_[A-Za-z0-9]{20,}|github_pat_" \
  landscape-scans/*.md
rc=$?                      # capture IMMEDIATELY - $? is clobbered by the next command
case "$rc" in
  0) echo "LEAK: internal identifiers found above - FAIL" ;;
  1) echo "no internal identifiers: OK" ;;
  *) echo "GREP ERRORED (status $rc) - this step did NOT run. Do not record a pass." ;;
esac
```

**Expect:** one hit for the scope note; **no** internal identifiers.

**Two families, and the pattern is deliberately generalised past the ids we happen to
have today.**

- **Prefixed internal resource ids** — `(trig|env|wf|conn)_…`. An earlier version matched
  `trig_` alone, which would have let the routine's own `env_…` environment id through
  while printing a reassuring `OK`. The version before *that* matched no UUIDs, so a
  leaked Jira cloudId would have passed too. **This check has now been too narrow twice**;
  generalising the prefix is what stops a third time.
- **Credential prefixes** — `sk-ant-`, `ghp_`/`gho_`/`ghu_`/`ghs_`, `github_pat_`. The
  scope note bans credentials and the pattern had never looked for one. Leaking a key is
  the catastrophic case, and these prefixes essentially never false-positive.

**Deliberately NOT matched: private IPs and internal hostnames.** The scope note bans
them, but `localhost:4318` is explicitly allowed, and patterns for `10.x` / `192.168.x` /
`.local` would fire on documentation far more often than on a real leak. A check that
cries wolf gets waved through, which is worse than not having it.

It scans **every** file in the directory, not just `_evaluated.md` — the scan reports are
equally public.

**Negative control — run it, or the pattern is unproven.** One planted string per family:

```bash
printf 'a env_01ABCDEFGHIJKLMNOPQRSTUV b\n'                  > $WX389_TMP/leak1.md
printf 'a 12345678-1234-1234-1234-123456789abc b\n'          > $WX389_TMP/leak2.md
printf 'a sk-ant-EXAMPLENOTREAL b\n'                         > $WX389_TMP/leak3.md
printf 'a ghp_ABCDEFGHIJKLMNOPQRSTUVWXYZ012345 b\n'          > $WX389_TMP/leak4.md
for f in $WX389_TMP/leak1.md $WX389_TMP/leak2.md $WX389_TMP/leak3.md $WX389_TMP/leak4.md; do
  grep -qEi "(trig|env|wf|conn)_[A-Za-z0-9]{20,}|connector_uuid|[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}|sk-ant-|gh[pous]_[A-Za-z0-9]{20,}|github_pat_" "$f" \
    && echo "  $f: caught" || echo "  $f: MISSED -- pattern is dead for this family"
done
rm -f $WX389_TMP/leak1.md $WX389_TMP/leak2.md $WX389_TMP/leak3.md $WX389_TMP/leak4.md
```

**Expect:** all four `caught`. Any `MISSED` means that family is unprotected.

Then **read the file** against its scope note — the grep only catches what it has a
pattern for, and the reading catches what no regex can express. `PaulHarder2/HarderWare`
is public. `_evaluated.md` **is** reviewed by CodeRabbit as of WX-389, but CodeRabbit
reviews *changes*: any line carried forward untouched has never been read by anything but
us, so **treat standing content as unreviewed**. The generated reports
(`landscape-scans/20*.md`) remain excluded and have no reviewer at all.

## Steps 3–9 — 2026-09-01 or later (routine half)

### 3. The routine actually fired

Fetch the routine (`RemoteTrigger` action `get`; trigger id is on the ticket).

**Expect:** `last_fired_at` is on or after 2026-09-01T13:07Z.
**If it is not, STOP.** Nothing below is meaningful, and the finding is that the routine
stopped running — which looks identical to a quiet month.

### 4. The email closes with the decision-loop reminder

Open the Gmail draft for `landscape-scan 2026-09`.

**Expect:** the **last block in the message body** tells us to add a `## YYYY-MM` section
to `landscape-scans/_evaluated.md` under **Decisions by scan**, and states that a
decision recorded there will not be raised again. Applies on quiet months too.

### 5. The scan report carries a back-link — check the TARGET STRING, not the click

⚠️ **Do not verify this by clicking.** At the moment this step runs, the `## 2026-09`
section does not yet exist — creating it is the *last* step of reacting to the scan. A
markdown link to a missing anchor lands silently at the top of the file, so a correct
link and a typo'd one look identical. Clicking here would be a check that cannot fail.

```bash
tail -5 landscape-scans/2026-09.md
grep -n "_evaluated.md#2026-09" landscape-scans/2026-09.md
```

**Expect:** the file ends with a `**Decisions.**` footer whose link target is exactly
`_evaluated.md#2026-09`, including the sentence that an absent section means the scan has
not been dispositioned.

**Then, after the `## 2026-09` section has been written** (i.e. once the scan has been
reacted to), click the link and confirm it lands on that section. Record both halves.

### 6. No finding asserts local-environment state

Read every finding.

**Expect:** no claim about which model Claude Code runs, installed versions, subscription
tiers, or local settings is stated as **fact**. Such things appear hedged, or as a
question, or not at all.

**This is the specific regression:** the 2026-08 scan asserted Claude Code was on an
older Opus model when it had already been upgraded.

### 7. Every recommended command can answer its own question

For each **Recommended next step** that is a command, ask: *what would this print if the
work were already done, and could the reader tell?*

**Expect:** each one discriminates, and the finding says what output means *act* versus
*already fine*.

**This is the specific regression:** the 2026-08 scan recommended `dotnet --version` to
test a .NET **8** runtime patch level; it reports the SDK and cannot answer that at all.

### 8. Settled items are not resurfaced

**Expect:** the scan does **not** recommend adopting Claude Opus 5 for Claude Code
(Adopted), and does **not** re-raise Sonnet 5 as a cost saving, CodeRabbit Post-Merge
Actions, Sentry/Seer, or Rovo Dev (Deferred/Declined).

**Unless** it names the entry, quotes the re-evaluate trigger it believes fired, and
gives evidence — that is a **pass**, not a failure; it is the mechanism working.

⚠️ **But check the trigger it quotes was not ALREADY SATISFIED when the entry was
written.** Such a trigger has effectively always been fired, so a scan quoting it scores
as a pass while the guard did nothing. If you find one, the defect is in `_evaluated.md`,
not in the scan.

**A future date is NOT that defect.** The Sonnet 5 entry's `2026-12-01` backstop names a
date rather than a change, deliberately — it was false when written and fires exactly
once. The test is *"was this true on the day it was written?"*, not *"is this phrased as
a change?"*

### 9. Also confirm the "already satisfied" verdicts were not re-raised

**Expect:** the scan does not re-raise the .NET 8 runtime patch or the
`claude-opus-4-1` retirement as open actions. These carry **no disposition entry** — they
exist only as rows in the 2026-08 register — so this step checks the half of the
mechanism that the dispositions cannot cover.
