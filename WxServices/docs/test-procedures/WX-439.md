# WX-439 — Manual test procedure

**Ticket:** WX-439 — enable the Grafana `pinNavItems` feature toggle so dashboards are reachable from
the left nav.
**Release:** none — no version bump. One environment variable in `observability/docker-compose.yml`;
it ships in no service binary, so `Directory.Build.props` and `VERSIONS.md` are untouched (WORKFLOW §5).

## What this checks, and what it deliberately does not

**The runtime effect has been live on the production machine since 2026-08-14** as an uncommitted
working-tree edit. So the browser steps **cannot** distinguish *"the merged change works"* from *"it
was already working"* — they confirm the merge disturbed nothing, and that is all they are for.

The measurement that establishes the toggle is what gates the nav was taken on 2026-08-14 and is
recorded in **WX-439's own description**: before it, neither starring nor bookmarking reached the nav;
after it, both did. Re-running it means deliberately breaking production's nav to re-prove a known
result.

🔑 **The one thing genuinely worth verifying is AC-2** — that the local edit was *reconciled*, not left
coexisting with an identical committed line. Everything on this machine already looks right, which is
exactly why that is the check that gets skipped, and it is the reason this ticket exists.

Run after the PR is merged, from the repo root.

## Steps

1. **The git assertions.**

   ```bash
   git fetch origin
   git rev-parse --abbrev-ref HEAD                          # expect: master
   git rev-parse HEAD; git rev-parse origin/master          # expect: identical
   git show origin/master:observability/docker-compose.yml |
     grep -cE '^[[:space:]]*-[[:space:]]*GF_FEATURE_TOGGLES_ENABLE=pinNavItems[[:space:]]*$'
                                                            # expect: 1          <- AC-1
   git show origin/master:observability/docker-compose.yml |
     cmp - observability/docker-compose.yml                  # expect: silent, rc=0  <- AC-2
   ```

   ⚠️ **Three traps, each measured, each the reason its command is written the way it is.**
   **`git fetch` is not optional** — `origin/master` is a *local* ref, and a stale one reports a
   spurious AC-1 failure immediately after a browser merge.
   **The grep is anchored** because an unanchored substring match returns `1` for a commented-out line
   and for a typo'd value such as `…=pinNavItemsXYZ`.
   **`cmp` is used rather than `git status`**, whose pass condition is *"printed nothing"* — which is
   also what a **mistyped path** prints, and what `git update-index --assume-unchanged` prints over a
   genuinely edited file. `cmp` reads real bytes and cannot be fooled either way.

2. **Open `http://localhost:3000` and refresh the browser (Ctrl+F5).** Look at the left nav.

   *Expect:* a **Starred** and/or **Bookmarks** section, listing whatever is starred or bookmarked.
   **AC-4.** The nav does not repopulate on its own, so an absent section is not a failure until the
   page has been refreshed. **No container recreate is needed** — the running container already
   carries the toggle.

3. **Dashboards → Browse.**

   *Expect:* **WxMonitor**, **WxParser**, **WxReport** and **WxVis** are listed, and each **opens**.
   **AC-5, the negative control against a fix that over-reaches** — the toggle must add a route
   without disturbing provisioning. Browse lists *titles*; the UIDs (`wxmonitor-v1`, `wxparser-v1`,
   `wxreport-v1`, `wxvis-v1`) appear only in the URL and are what would 404 if provisioning had been
   disturbed, which is how the WX-278 regression presented.
