# WX-439 — Manual test procedure

**Ticket:** WX-439 — enable the Grafana `pinNavItems` feature toggle so dashboards are reachable from
the left nav.
**Release:** none — no version bump. The change is one environment variable in
`observability/docker-compose.yml`; it ships in no service binary, so `Directory.Build.props` and
`VERSIONS.md` are untouched (WORKFLOW §5).
**Component:** the `grafana` container of the observability stack. Verified interactively — the effect
is a browser UI change, so there is nothing for the unit suite to assert.

**What changed:** one line in the `grafana` service's `environment:` block —

```yaml
      - GF_FEATURE_TOGGLES_ENABLE=pinNavItems
```

With the toggle on, Grafana's left nav gains a **Starred** section and a **Bookmarks** section, so a
starred or bookmarked dashboard is one click away instead of requiring Dashboards → Browse every time.

## 🔴 READ THIS BEFORE STEP 1 — what this procedure can and cannot prove

**The runtime effect has been live on the production machine since 2026-08-14** as an uncommitted
working-tree edit. So steps 4–6 below, run on their own, **cannot distinguish "the merged change
works" from "it was already working before the merge"** — they would pass either way.

Two things close that gap, and both are stated rather than assumed:

- **The discriminating before/after already exists and is not re-run here.** It was observed on
  2026-08-14: before the toggle the nav had no route to the dashboards, and neither starring nor
  bookmarking produced one; after the toggle, both did. That is the measurement that establishes the
  toggle is what gates the nav. Re-running it means deliberately breaking production's Grafana nav to
  re-prove a known result, which is not worth it.
- **Step 3 is what this procedure actually adds**: it proves the container is running from the
  **committed** file rather than from the local edit. That is the whole point of the ticket, and it is
  the one thing that was not true before the merge.

**So the verdict below turns on steps 1–3.** Steps 4–6 are confirmation that the merge did not
disturb a working state, not evidence that the toggle works.

**Setup:** run after the PR is merged to `master` and the working tree is reconciled (AC-2). All
commands from `/mnt/c/Code/HarderWare` unless noted; the Docker commands need Docker Desktop running.

Read one step at a time; report the result of each. Note any failure and continue; the failed-step
list is the deliverable.

## Steps

1. On PaulOmniBook, confirm the line is on `master` and the working tree is clean:

   ```bash
   git log --oneline -1 origin/master
   git show origin/master:observability/docker-compose.yml | grep -c 'GF_FEATURE_TOGGLES_ENABLE=pinNavItems'
   git status --short observability/docker-compose.yml
   ```

   *Expect:* the `grep -c` prints **`1`**; `git status --short` prints **nothing at all** for that
   file. **AC-1 and AC-2.**
   ⚠️ Empty output from `git status --short` is the pass condition here, so confirm the command ran —
   a typo in the path also prints nothing. `git status --short observability/zzqqxx.yml` is the
   negative control and likewise prints nothing, which is exactly why the `grep -c` above carries the
   positive half.

2. Recreate Grafana **from the committed tree**:

   ```bash
   cd observability && docker compose up -d grafana
   ```

   *Expect:* the command completes and `docker ps` shows `observability-grafana-1` up. Only Grafana is
   recreated — the other containers are untouched. The baked dashboards survive (they live in the
   image, WX-278) and stars survive (they live in the `grafana-data` named volume, which is not
   removed).

3. Confirm the running container carries the toggle:

   ```bash
   docker inspect observability-grafana-1 \
     --format '{{range .Config.Env}}{{println .}}{{end}}' | grep GF_FEATURE_TOGGLES_ENABLE
   ```

   *Expect:* exactly `GF_FEATURE_TOGGLES_ENABLE=pinNavItems`. Because step 2 recreated the container
   from the committed file, this is the fingerprint that the **merged** change is what is running.
   ⚠️ **Grep for the one variable; do not dump the whole environment.** `GF_SECURITY_ADMIN_PASSWORD`
   is in that list in plaintext, and an unfiltered dump puts it into the terminal, the scrollback and
   any transcript.

4. Open Grafana at `http://localhost:3000` and **refresh the browser** (Ctrl+F5). Look at the left nav.

   *Expect:* a **Starred** section and/or a **Bookmarks** section is present, listing the dashboards
   that were starred or bookmarked. **AC-4.**
   ⚠️ The nav does not repopulate on its own after a container recreate — the refresh is required. A
   nav with no such section on a stale page is not a failure until it has been refreshed.

5. If no dashboard is currently starred, star one (the ☆ beside a dashboard's title) and refresh.

   *Expect:* it appears under **Starred** in the left nav. Starring alone is sufficient — bookmarking
   is a second route to the same place, not a prerequisite.

6. Go to **Dashboards → Browse**.

   *Expect:* all four provisioned dashboards are listed — `wxmonitor-v1`, `wxparser-v1`,
   `wxreport-v1`, `wxvis-v1` — and each opens. **AC-5, the negative control against a fix that
   over-reaches:** the toggle must add a route without disturbing provisioning.

## Verdict

- **PASS** — steps 1–3 hold: the line is on `master`, `git status` is clean for that file, and the
  recreated container carries the toggle; and steps 4–6 confirm the nav route is present and the four
  dashboards still register. Record `PASS yyyy-mm-dd` in **Test Result**.
- **FAIL** — record the failed step(s) and the observed behaviour.
