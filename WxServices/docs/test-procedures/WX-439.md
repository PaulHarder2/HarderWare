# WX-439 — Manual test procedure

**Ticket:** WX-439 — enable the Grafana `pinNavItems` feature toggle so dashboards are reachable from
the left nav.
**Release:** none — no version bump. One environment variable in `observability/docker-compose.yml`;
it ships in no service binary, so `Directory.Build.props` and `VERSIONS.md` are untouched (WORKFLOW §5).
**Prerequisites:** `python3` with **PyYAML** (`import yaml`), and Docker Desktop running. PyYAML is
present on PaulOmniBook (6.0.3) and unmeasured elsewhere; if it is missing, step 1's AC-1 command
prints a `ModuleNotFoundError` and **no verdict at all** — which is a failure to evaluate, not a FAIL.
🔴 **Run this on PaulOmniBook.** AC-2 is machine-scoped — it is *that machine's* working-tree edit that
has to be reconciled. Every assertion below passes on any other clone while the divergent edit sits
untouched, which would record AC-2 as met on the one machine where it is not.

## What this checks, and what it deliberately does not

**The runtime effect has been live on PaulOmniBook since 2026-08-14** as an uncommitted working-tree
edit. So the browser steps **cannot** distinguish *"the merged change works"* from *"it was already
working"* — they confirm the merge disturbed nothing, and that is all they are for.

The measurement that establishes the toggle is what gates the nav was taken on 2026-08-14 and is
recorded in **WX-439's own description**: before it, neither starring nor bookmarking reached the nav;
after it, both did. Re-running it means deliberately breaking production's nav to re-prove a known
result.

🔑 **The one thing genuinely worth verifying is AC-2** — that the local edit was *reconciled*, not left
coexisting with an identical committed line. Everything on this machine already looks right, which is
exactly why that is the check that gets skipped, and it is the reason this ticket exists.

Run after the PR is merged, from the repo root.

## Steps

1. **The git assertions.**

   ```bash
   git fetch origin
   git rev-parse HEAD; git rev-parse origin/master     # expect: identical            <- AC-2
   git status --porcelain -- observability/docker-compose.yml   # expect: no output   <- AC-2
   git show origin/master:observability/docker-compose.yml | cmp - observability/docker-compose.yml
                                                       # expect: silent, rc=0         <- AC-2
   git show origin/master:observability/docker-compose.yml | python3 -c 'import sys,yaml; d=yaml.safe_load(sys.stdin) or sys.exit("AC-1 ERROR: empty blob - check the path"); e=d["services"]["grafana"].get("environment",[]); p=e if isinstance(e,dict) else dict(x.split("=",1) for x in e if "=" in x); print("AC-1 PASS" if "pinNavItems" in str(p.get("GF_FEATURE_TOGGLES_ENABLE","")).replace(","," ").split() else "AC-1 FAIL")'
                                                       # expect: AC-1 PASS            <- AC-1
   ```

   🔴 **AC-2 NEEDS ALL THREE OF ITS COMMANDS. They are complementary, and each one alone returns a
   false PASS in a state the others catch.** Measured in a scratch repo:

   ```
   local still at the pre-merge commit, toggle edit STILL UNCOMMITTED, after git fetch:
     cmp origin/master:blob vs worktree   silent, rc=0   -> PASS   *** FALSE ***
     git status --porcelain               " M compose.yml"        correctly FAILS
   ```

   `cmp` compares the **remote blob** against the **on-disk bytes**; content equality does not imply
   the file was ever committed or pulled — which is precisely the "not merely coexisting" state AC-2
   is worded against. Conversely `git status` alone is fooled by `git update-index
   --assume-unchanged` over a genuinely edited file, and prints nothing for a **mistyped path** —
   indistinguishable from its own pass condition. `cmp` answers that, because a bad path there fails
   loudly. And `HEAD == origin/master` is what proves the merge was actually pulled rather than
   the branch merely being content-identical.

   ⚠️ **AC-1 parses the YAML rather than grepping it, and the reason is a FALSE PASS.** A line-oriented
   grep is blind to *which service block* the line sits in: measured, with the toggle relocated into
   `prometheus:`, an anchored grep still returned `1` while Grafana never receives the variable — and
   `cmp` cannot see it either, since blob and worktree agree. The parse is correct across seven
   measured cases: correct→PASS, absent→FAIL, relocated-to-`prometheus`→FAIL, `pinNavItems,otherToggle`
   →PASS, `otherToggle, pinNavItems` **with a space**→PASS, commented-out→FAIL, `environment:` as a
   mapping→PASS. The value is split on commas **and whitespace** because Grafana's own parser accepts
   both; splitting on commas alone gives a spurious FAIL on the spaced form.

   ⚠️ **`git fetch` is not optional.** `origin/master` is a *local* ref, and a stale one reports a
   spurious AC-1 failure immediately after a browser merge.

   ⚠️ **Two failure signatures worth reading rather than just checking `rc`.** A typo in the **AC-1**
   blob path prints `AC-1 ERROR: empty blob - check the path`. A typo in the **`cmp`** blob path
   prints `cmp: EOF on '-' which is empty` rather than a content difference. Both are path problems
   wearing content-problem clothing.
   ⚠️ **`cmp` is not eol-normalising**, so on a clone with `core.autocrlf=true` it reports a
   difference that is not one. `.gitattributes` pins LF for `*.sh` and `*.cs` but **not** `*.yml`;
   `autocrlf` is unset on PaulOmniBook and unmeasured on PAUL-ZBOOK. Spurious FAIL, never a false PASS.

2. **Recreate Grafana, then open `http://localhost:3000` and refresh the browser (Ctrl+F5).**

   ```bash
   ( cd observability && docker compose up -d --force-recreate grafana )
   ```

   *Expect:* the left nav shows a **Starred** and/or **Bookmarks** section. **AC-4.**
   ⚠️ The nav does not repopulate on its own, so an absent section is not a failure until the page has
   been refreshed. `--force-recreate` is required for the recreate to happen at all — plain
   `docker compose up -d grafana` is a **no-op** when the compose file has not changed since the
   container was built (measured: `--dry-run` prints `Running` for the plain form, `Recreated` only
   with the flag). The `grafana-data` named volume is untouched, so stars survive; the dashboards are
   baked into the image (WX-278).

3. **Dashboards → Browse.**

   *Expect:* **WxMonitor**, **WxParser**, **WxReport** and **WxVis** are listed, and each **opens**.
   **AC-5, the negative control against a fix that over-reaches** — the toggle must add a route
   without disturbing provisioning. Browse lists *titles*; the UIDs (`wxmonitor-v1`, `wxparser-v1`,
   `wxreport-v1`, `wxvis-v1`) appear only in the URL and are what would 404 if provisioning had been
   disturbed, which is how the WX-278 regression presented.

   **Then, if step 2 showed no Starred section because nothing is starred: star one of these
   dashboards here (the ☆ on its row or beside its title) and refresh.** *Expect:* it appears under
   **Starred** in the left nav.
   🔑 **This is what makes step 2 a real observation rather than a vacuous one** — an empty nav section
   is otherwise indistinguishable from an absent toggle, and this is the only runtime evidence in the
   procedure. It sits here rather than in step 2 because Browse is where the ☆ is reachable; at
   step 2 the executor is on the Grafana home page with nothing obvious to star.
