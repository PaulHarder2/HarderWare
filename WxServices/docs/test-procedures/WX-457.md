# Verifying a comments-only trim

**Reusable.** `--file` and `--base` point it at the next trim; `ReportWorker.cs` is the intended
next subject.

⚠️ **ONE FILE PER RUN.** The scripts take a single path. A change touching several files needs one
invocation each — there is no multi-file mode, and a run says nothing about files it was not given.

## What this proves, and what it cannot

Three reviewers read the WX-457 diff and found twelve defects between them. **Four of the mechanical
ones were found only by these scripts**, and one was created *by a repair* two hours after every
reviewer's pass — unreachable by reading, by construction.

🔴 **BUT IT CANNOT TELL WHETHER A COMMENT IS TRUE.** Every serious finding in that review was an
inverted meaning, a rule asserting more than the code enforces, or a doc left false by a deleted
qualifier. Reviewers found all of them; no script could have. **A green run means nothing mechanical
is broken. It never means the change is good.**

## Run it

    cd WxServices
    ./docs/test-procedures/WX-457-verify.sh                       # defaults
    ./docs/test-procedures/WX-457-verify.sh --file PATH --base REV --head REV
    ./docs/test-procedures/WX-457-verify.sh --selftest

Both revisions come **from git**, never a working copy — a verification depending on an unversioned
artifact cannot be re-run by anyone else.

## Exit codes, and the third one matters most

    0  every check passed
    1  a check FAILED
    2  usage / lookup error
    3  a check COULD NOT RUN — NEVER a pass

## The architecture, in one rule

🔴 **EVERY CHECK IS SCORED BY ITS EXIT STATUS, NEVER BY ITS OUTPUT TEXT.** An earlier version
grepped stdout for `FAIL` through a pipe; under `set -o pipefail` the pipeline returned the
*checker's* non-zero rather than grep's zero, so the test was false exactly when a guard **had**
failed. **Guards 1–3 could never fail the run.** If you add a check, capture its `rc` directly.

## What it checks

| # | Check | Scored? |
|---|---|---|
| **1** | **AC-1** — strip comments from both revisions, compare surviving code | yes; `3` if the stripper cannot trust its own parse |
| **2** | **Positive control** — plant a real code change and require AC-1 to detect it | yes |
| **3** | **Guard delta** — findings this change *introduced* | yes |
| **4** | Absolute guard state, both revisions | no — context |
| **5** | `///` content delta | no — informational |

**Guards:** comment blocks opening lowercase (own-line comments only); doubled words, including
across a re-flowed line join; a comment ending on a dangling `—`, `:` or `(`.

## Four things that must not be simplified away

🔴 **[3] is scored by COMPARISON, not by the after-file being clean.** A finding in both revisions is
a pre-existing habit; only what the change *added* is its fault. Scoring them separately made any
file with existing habits permanently unpassable — and this file had four.

🔴 **The run REFUSES when base and head are the same commit, or the file is identical at both.**
Once this branch merges, `origin/master` equals `HEAD` and the default invocation would compare a
file with itself: every check passes on an empty diff and the banner still says PASS. **A
verification that quietly becomes a no-op the moment it lands is worse than none.**

🔴 **The positive control plants CODE, and must target a line AC-1 can see.** An earlier version
inserted `/*x*/` — a comment — which AC-1 correctly ignored, so the control reported failure while
the check worked perfectly. It aborts loudly if the mutation cannot be applied, because a mutation
that silently fails to apply looks exactly like a kill. ⚠️ **The control shares the stripper with
the check, so it can prove the stripper distinguishes *some* change — never that it sees *this
file's* code.** That gap is what AC-1's own suspicion guard covers.

🔴 **AC-1 refuses rather than guessing.** It exits `3` if the parse ends unbalanced, or if a
**code-looking line was consumed as a comment** — the durable guard against any stripper blind spot.
This exists because the stripper once mis-parsed C# 11 raw strings and **deleted real code from both
revisions identically**, reporting "comments-only proven" on a changed integer literal. 15 `.cs`
files here use `"""`.

⚠️ **"Identical" means after whitespace normalisation**, not byte-identical: leading and trailing
space is stripped and blank lines dropped before comparing. A change to indentation alone will not
be reported.

## Selftests

`--selftest` runs both. **Each guard has a fixture that only that guard detects, so gutting any
guard makes the selftest fail** — verified by actually gutting one. There are false-positive
controls too: commented-out code must not trip AC-1's suspicion guard, and a legitimate new sentence
across a line join must not read as a doubled word.

## Expected result

    [1] AC-1 PASS   [2] planted change detected   [3] 0 introduced   ====> PASS

A `FAIL` on [3] means the change introduced it. A `FAIL` on **[2]** means the verification itself is
broken — fix that before believing any other line.
