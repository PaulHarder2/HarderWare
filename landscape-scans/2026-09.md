- The 2026-12-01 calendar backstop has not fired.

**Cost to add.** ~13% effective savings on API token spend once migrated.

**Recommended next step.** This reopens the question the deferral closed: do you want to schedule a working session now rather than wait for the retirement trigger? The remaining work: remove `temperature` from both request objects in `ClaudeClient.cs` (lines 213, 405); run real reconciliation and translation cycles; update `"Model"` in `appsettings.shared.json` if quality holds. The other deferral triggers still allow waiting — the pricing case just reversed.

### 2. Claude Fable 5 — Opus 5 Adoption Trigger Check (Verdict: Stay on Opus 5)

**What changed.** Claude Fable 5 (`claude-fable-5`) was released June 9, 2026 at $10/$50 per MTok. It is Anthropic's highest-capability widely released model. The Opus 5 adoption entry carries this trigger: *"A newer model…is otherwise the better tier for long-horizon multi-file work."* This check is against that trigger; the verdict is no upgrade.

**Why Opus 5 wins for Claude Code.** Three factors:

1. **2× the price** ($10/$50 vs $5/$25 per MTok).
2. **Older reliable knowledge cutoff** — January 2026 vs Opus 5's May 2026. For a coding assistant, more current knowledge of the ecosystem matters.
3. **Safety classifiers that can decline requests.** The Fable 5 model page explicitly calls out new refusal-handling requirements for integrations. In an interactive coding session, mid-task refusals are disruptive; Opus 5 does not carry this behavior.

Fable 5's "adaptive thinking always on" is better suited to deep standalone reasoning than iterative multi-turn coding. No change for the WxServices runtime: $10/$50 is not appropriate for single-turn structured tool-use calls.

**Cost to add.** 2× Opus 5 pricing.

**Recommended next step.** No action required. Record the trigger-check outcome in `_evaluated.md` so the scan knows the check ran.

- https://platform.claude.com/docs/en/about-claude/models/overview
