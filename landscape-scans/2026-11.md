## Actionable Findings

### 1. .NET 8 and .NET 9 End of Life — November 10, 2026 (9 days away)

**What changed.** Microsoft ends support for both .NET 8 (LTS) and .NET 9 (STS) on November 10, 2026. No further security patches will be issued after that date. The most recent .NET 8 patch was 8.0.33 (October 25, 2026), which fixed three CVEs including CVE-2026-70197, a SocketAsyncEventArgs memory corruption issue on Windows. .NET 10 LTS shipped November 11, 2025 and is supported through November 2028.

**Why it matters for Paul's stack.** All WxServices projects target `net8.0` (verified: WxReport.Svc.csproj, WxServices.Common.csproj; the pattern is consistent across the project). After EOL, the runtime remains functional but receives no CVE fixes. .NET 9 cannot serve as an intermediate target — it expires on the same day. The only currently active upgrade target is .NET 10 LTS (`net10.0`).

**Cost to add.** Free (SDK download). Engineering time: change `TargetFramework` in all `.csproj` files from `net8.0` to `net10.0`; update `Microsoft.Extensions.*` packages from `8.0.0` to their `10.x` equivalents; retest.

**Recommended next step.** `dotnet --list-runtimes | grep 'NETCore.App 10'` — output present means .NET 10 runtime is installed and the TFM migration can start; empty output means install the .NET 10 SDK first, then migrate.

### 2. API Version 2026-10-21 — Correction to Sonnet Deferral Entry, Reason 3

**What changed.** Anthropic released API version `2026-10-21` (the version name is the release date: October 21, 2026). On this version, `temperature`, `top_p`, and `top_k` return HTTP 400 on **all models**, including `claude-sonnet-4-6`. On version `2023-06-01` — which WxServices uses — temperature continues to work on `claude-sonnet-4-6`. The migration guide explicitly states: *"If a request relies on a non-default value [of temperature], either stop sending the parameter, or keep that request on `2023-06-01`."*

**Why it matters for Paul's stack.** This is a **correction** to reason 3 of the Sonnet deferral entry: the "platform direction" claim is now formalized as an API version contract, not just per-model behavior. Practical alert: do **not** change `"ApiVersion": "2023-06-01"` in `appsettings.shared.json` to `2026-10-21` until `temperature` is removed from `ClaudeClient.cs` — doing so would immediately break all Claude calls. WxServices uses raw `HttpClient` with no Anthropic C# SDK reference; the C# SDK v13.0.0 requirement in the migration guide does not apply.

**Cost to add.** N/A — correction, not an adoption recommendation.

**Recommended next step.** Record the correction in `_evaluated.md` under the Sonnet deferral entry. No code change before the December working session.

### 3. Claude Haiku 5.5 — New Model (October 7, 2026)

**What changed.** `claude-haiku-5-5` released October 7, 2026 at $0.10 / $0.50 per MTok — 20× cheaper than Sonnet 5.5 ($2/$10). Adaptive thinking, 1M context window. Positioned for "high-volume, latency-sensitive tasks such as classification, extraction, and routing." Retirement not sooner than October 7, 2027.

**Verdict — Claude Code role (b): Declined.** Haiku tier is explicitly for classification and routing, not long-horizon multi-file coding work. Add `claude-haiku-5-5` to the Opus entry's evaluated set.

**Verdict — WxServices runtime role (a): Defer to December migration window.** The Sonnet deferral entry covers only `claude-sonnet-5` and `claude-sonnet-5-5`; Haiku 5.5 is a separate evaluation. At 20× cheaper than Sonnet 5.5, a quality test is worth running during December migration: compare reconciler and translator output against `claude-sonnet-4-6` baselines before deciding. The model page says "Omit `temperature`, `top_p`, and `top_k`" — same breaking change requirement as Sonnet 5.5 applies to all call paths. Forced `tool_choice` behavior is **not** stated on the model page; check the Haiku 5.5 migration guide before adopting.

**Cost to add.** $0.10 / $0.50 per MTok (inference) if quality holds.

**Recommended next step.** Record `claude-haiku-5-5` as Declined for Claude Code in `_evaluated.md`. For the runtime role, evaluate during the December migration window alongside Sonnet 5.5.
